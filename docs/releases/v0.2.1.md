Leaf Juice can now give Packmule each new pack build (D189).

## Added

- **`/packmule pack set <pack> <url>`** points a pack at a new per-build address. The address must be https, with the pack's SHA-1 as the file name. Packmule downloads the file first and checks that its SHA-1 matches. Only then does it write the new address to `config.yml`, keeping the file's comments, and reload. A refusal leaves the old address and the config untouched. Permission `packmule.pack.set`, op by default.
- **`--json <id>`** on `pack set` and the new `/packmule describe` gives one-line answers in the Signalbox format, for Leaf Juice. A pass answers `{"ok":true,"pack":"main","sha1":"…","check":"passed"}`. Refusals carry a code: `bad-argument`, `not-found`, `check-failed`, `busy` or `config-problem`.

## Upgrading

Replace the jar and restart. Nothing else changes. The ResourcePackButler names still work in 0.2.x.

## Tested

47 unit tests pass. They cover refusing every address that isn't an https per-build one, refusing an unknown pack, the config edit keeping comments and other packs, a file that doesn't match its name failing the check, and `describe`. Not yet run on a server with bots, or called by Leaf Juice.
